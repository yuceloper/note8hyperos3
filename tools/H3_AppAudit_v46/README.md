# Audit communication app provenance before integration changes

User requested examination of donor HyperOS and suspected Google Phone/Contacts/Messages were introduced by the port. This is a hypothesis, not a verified fact. Existing repo docs name creek Turkey HyperOS3 as donor and mention a Google setup state; searched default-branch code/commit text provided no origin evidence. Early offline APK selection predates the documented V12 baseline, so Git alone may not explain it.

Use audit.py in ginkgo-camera-apk-tools:v27 with --entrypoint python3, tools mounted /tools:ro, note8-hyperos3-work mounted /linux:ro, and host out/app-audit-v46 mounted /out. The script reads every APK manifest with aapt, not guessed filenames. It writes complete inventories and computes SHA256 for the communication scope, including original/donor and Google packages. Parse errors are recorded and make the report incomplete, not evidence of package absence. It does not alter source/ROM trees.

Then run collect_device.py on Mac. It bundles the offline report with installed package paths, disabled packages, live Phone/SMS roles, communication package state and overlay list. No user messages, contacts DB, app data or signing keys are collected; package dumps may contain installation metadata. The script does not set roles, uninstall Google apps, install Xiaomi APKs or flash.

Interpretation: matching donor/work-tree hashes prove bytes already exist in the local donor tree. This alone does not prove that donor tree matches an untouched official image; if unexpectedly changed, compare original donor images next. ONLY_IN_WORK_TREE identifies additions relative to the source tree. ONLY_IN_DONOR identifies source APKs absent from the port tree (provided inventories are complete). Runtime package paths identify userdata updates; default roles and enabled state are separate from physical APK presence. Do not infer original regional app selection from a missing fallback component alone.
