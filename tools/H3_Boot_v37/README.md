# V37 boot timeline collector

This is a diagnostic tool, not a new ROM. Run from the Mac repository root with `python3 tools/H3_Boot_v37/collect.py --reboot`. The explicit flag requests exactly one reboot of serial 12da33e7 after verifying ro.product.device=ginkgo and reading its previous boot ID. No app settings, permissions, policy, files or partitions are changed on the phone. Root is not required. The collector never enters recovery/fastboot or flashes anything.

Enter the SIM PIN and device lock normally after reboot. Do not open the camera or heavy applications during this baseline. Keep the cable connected. The script waits up to 120 seconds for a different boot ID, then records 180 seconds by default. Progress prints approximately every 15 seconds; slow/timeout commands can shift cadence. Every sample stores device uptime and host elapsed time so those shifts remain visible.

Basic samples: boot completion, SIM state, operator label, network type, phone/system_server PIDs, aggregate /proc/stat CPU counters, memory/vmstat and optional PSI. Overall CPU busy percentages use successive counters, exclude guest double counting and are not per-app attribution. Top takes two samples separated by one second about every 15 seconds. Registry output is reduced to voice/data registration and radio technologies to avoid storing cell identity from that dump. Rootless denials/unsupported fields are recorded rather than patched around.

Logcat streams all available buffers from the new boot. This can contain personal identifiers: keep raw archives local/private and never commit them. Sampling starts after ADB becomes available, not at power-on; it cannot prove the exact time the PIN dialog appeared or when the user entered the PIN. SIM LOADED/operator text alone do not prove usable service. Registration changes are first observed times. Valid signal/functional call/data still require their own verification.

Artifacts under logs/v37-boot-TIMESTAMP include timeline.jsonl, registration.jsonl, summary.json, periodic top snapshots, logcat.txt, preflight.txt and events.json. Success and partial/incomplete sessions are archived; inspect events.json before interpreting missing data. If logcat disconnects the collector records/restarts its stream (duplicate buffered lines can appear). An unexpected further boot-ID change ends the session. No second reboot is attempted. Keep the archive for analysis, then optionally record manually when PIN was entered and when the UI/network felt ready; do not send the PIN itself.
